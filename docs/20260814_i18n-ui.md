# UI internationalization

## Goal

Internationalize the login UI for all 15 official ZITADEL languages, with reactive Solid translations, browser-language detection, persistent explicit language selection, runtime CSV loading, and English fallback.

## Decisions

- English UI text is the translation key and fallback.
- Every user-visible text expression is wrapped directly in `ttc("English text")`; translated results are not cached in component constants.
- Non-English translations live in `public/i18n/{lang}.csv` with `english,{lang}` columns and are fetched and parsed in the browser at runtime.
- The supported language codes are `en`, `de`, `it`, `es`, `fr`, `nl`, `pl`, `pt`, `zh`, `ru`, `hu`, `tr`, `ja`, `uk`, and `ar`.
- Initial language follows the browser preference unless a user selection persisted in local storage overrides it.
- The language switcher sits by the theme switcher, uses the Material Design `language-alt` icon, and labels choices in their native languages.
- Implement and verify the complete English/German vertical slice before adding the remaining translation files.

## Approach

- Establish the current text, theme-switcher, test, and app-initialization architecture plus the preferred reference switcher design.
- Add a small reactive i18n boundary that owns language resolution, runtime CSV fetch/parsing, fallback, persistence, direction, and `ttc`.
- Integrate the switcher and convert all UI/test text through the translation function, then browser-test German switching, reload persistence, browser preference, fallback, and theme-switcher coexistence.
- Produce remaining language CSVs in parallel, integrate them, and run repository and browser verification across all supported languages.
